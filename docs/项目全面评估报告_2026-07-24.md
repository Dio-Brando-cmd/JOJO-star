# 帷幕之地 (VeilLand) — 项目全面评估报告

**日期:** 2026-07-24
**版本:** 2.13.1
**评估方法:** 全代码库审查 + 架构分析 + 进度对照

---

## 一、项目概览

帷幕之地是一个暗黑奇幻题材的多平台多人联机游戏，核心玩法是帷幕之地式社交推理（桌游模式）与非对称追逃（3D模式）的混合体。技术栈覆盖 Node.js 后端、React Web 前端、Electron 桌面端、Capacitor 安卓端、Unity 3D 客户端。

**当前阶段判断:** 核心桌游模式 (BOARD_GAME) 接近可玩但存在多个关键缺陷；3D 模式处于早期原型阶段；移动端体验不完整。

## 三、架构问题分析

### 3.1 关键架构缺陷

| 问题 | 严重程度 | 影响 | 建议 |
|------|---------|------|------|
| 单进程游戏服务器 | **严重** | 无法水平扩展，单点故障 | 引入 Redis 做房间状态存储，支持多进程 |
| 文件系统数据库 | **高** | 重启丢失数据风险，不支持并发 | 迁移到 SQLite（单机）或 PostgreSQL |
| 无消息队列 | **高** | 定时器基于 setTimeout，进程崩溃丢失 | 引入 Bull/BullMQ 做延迟任务 |
| 无 API 版本控制 | **中** | Socket 事件变更后旧客户端崩溃 | 添加协议版本协商 |
| 前端无状态管理库 | **中** | useSocket hook 承担了过多职责 | 引入 Zustand 或 Context 拆分 |
| 无错误边界 | **中** | 单个组件崩溃导致白屏 | 添加 React ErrorBoundary |
| 硬编码服务器地址 | **中** | 更换服务器需改代码重新构建 | 环境变量 + 服务发现 |

### 3.2 代码质量

- **Game.js (1289行):** 承担过多职责（游戏状态、角色分配、阶段转换、投票、3D模式、工具方法），建议拆分为多个 GameModule
- **NightResolver.js (45KB):** 功能完整但复杂度过高，缺少单元测试覆盖
- **constants.js (828行):** 常量定义 + 角色配置 + 步骤定义 + 身份数据混合，建议拆分
- **前端的 index.css (2648行):** 全项目样式集中在一个文件，建议按组件拆分

### 3.3 安全

- 密码使用 HMAC-SHA256 哈希（比明文好，但应该用 bcrypt/argon2）
- Socket.IO 连接无鉴权机制（任何人连接后可尝试加入任意房间）
- 无 CSP (Content Security Policy) 头
- 前端暴露了完整的服务器错误信息
