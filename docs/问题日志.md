## P1 · 下载包是 tar 不是 zip，客户端解压即失败（本次根因 ✅ 已确认）

- **症状**：玩家点「下载 3D 测试版」→ 下载到 `帷幕之地3D测试版.zip` → Windows 右键「全部解压」报错「压缩文件夹无效 / 不是有效的 zip 文件」→ 无法进入游戏。
- **根因**：打包命令用了 `tar -a -cf download/帷幕之地3D.zip ...`。Windows 自带的 bsdtar 的 `-a`（自动按后缀选压缩格式）**不认 `.zip` 后缀**（只认 `.gz/.bz2/.xz/.zst`），所以产出的其实是一个**未压缩 tar**，只是文件名叫 `.zip`。
- **快速定位（30 秒内确认）**：
  ```bash
  head -c 4 download/帷幕之地3D.zip | xxd
  # 真 zip  → 50 4b 03 04  (PK..)
  # 假 zip  → 56 65 69 6c  (VeilLand3D/，tar 头)
  file download/帷幕之地3D.zip   # 会显示 POSIX tar archive
  ```
  远端同理：`curl -s -r 0-15 'http://210.16.170.144:4000/download/%E5%B8%B7%E5%B9%95%E4%B9%8B%E5%9C%B03D.zip' | xxd`
- **修复**：改用 PowerShell 打包真 zip（之前 chase 已验证能压到 ~362MB）：
  ```powershell
  Compress-Archive -Path unity-build/VeilLand3D/* -DestinationPath download/帷幕之地3D.zip -CompressionLevel Optimal -Force
  ```
  打完再用 `head -c 4` 校验必须是 `PK`，然后删远端旧包 + 重传（见 P2）。
- **预防**：**永远用 `Compress-Archive` 打 `.zip`，禁止用 `tar` 打 `.zip`**。打包后强制校验 `PK` 魔数再上传。

## P2 · 续传脚本把「旧包」误判为「部分上传」，append 成损坏包（静默损坏）

- **症状**：上传后脚本打印「✅ 校验通过」，但客户端下载后 zip 损坏无法解压；或新旧包 size 恰好只差 10240 字节时**假校验通过**，实际内容是「旧包 + 新包尾巴」拼接的坏文件。
- **根因**：`upload-client-zip-resume.mjs` 第 31–39 行：只要远端已有文件（`!se && st`），就 `offset = st.size` 且 `flags='a'` 追加，把「远端已存在的旧包」当成「本次断点续传」的已完成部分。而校验只比 `st2.size !== total`（比大小，不比内容），新旧尺寸接近时能蒙混过关。
- **快速定位**：下载远端文件，`head -c 4` 看魔数 + `tail -c 4` 看是否出现第二段 zip 尾巴/异常；或 `zip -T`（真 zip 校验）直接报错。
- **修复**：
  1. 重传前先删远端：`node _reset-remote.mjs <密码>`（ssh2 `rm -f`）。
  2. 或把续传脚本改为「先校验远端首字节是否等于本地首字节，不等则强制 `flags='w'` 从 0 覆盖」。
- **预防**：**远端已存在旧包时，先 `rm` 再传**；续传逻辑必须校验「远端头部 == 本地头部」而不是只比 size；校验完成后再比一次 `md5sum` 而非只比 size。

## P3 · 大文件 SFTP 上传到 ~700MB 处 `read ECONNRESET`

- **症状**：`upload-client-zip.js`（单次全量）传 1.4GB 包，到 ~700MB 处报 `read ECONNRESET`，反复失败。
- **根因**：中间防火墙/ISP 对长连接大传输重置（非服务器问题——服务器磁盘 39G 空闲、pm2 online）。
- **快速定位**：日志在固定 ~700MB 断；用 `_reset-remote.mjs` 清空后换 `upload-client-zip-resume.mjs` 能继续。
- **修复**：用 `upload-client-zip-resume.mjs`（断点续传 + 自动重试，~0.7MB/s，1.4GB 约 30 分钟）。
- **预防**：**大文件一律走续传脚本**；小文件（<100MB）才用 `upload-client-zip.js`。

## P4 · 中文文件名 URL 未 percent-encode → 404

- **症状**：手动拼下载 URL `http://210.16.170.144:4000/download/帷幕之地3D.zip` 打不开（404），但页面按钮能下。
- **根因**：浏览器会自动 encode；手动/脚本拼 URL 时若直接塞中文，服务器收到的路径对不上静态文件。首字「帷」= `E5 B8 B7`，不是 `E5 B8 9A`（「幃」）。
- **快速定位**：`curl -I '正确encode的URL'` 应 200；未 encode 则 404。
- **修复**：用 `encodeURIComponent("帷幕之地3D.zip")` = `%E5%B8%B7%E5%B9%95%E4%B9%8B%E5%9C%B03D.zip`。
- **预防**：脚本/文档里写死 encode 后的完整 URL；别手算 UTF-8 字节。

## P5 · Unity 构建「成功」但 exe 未刷新（build 输出被截断，误判产物）

- **症状**：`BuildWindows.Build` 跑完以为出新包了，但 exe mtime 没变 / 没产出新 `unity-build` 内容。
- **根因**：Unity batch 命令接了 `| tail -25`，把「构建成功/失败」关键日志截断，结果没确认就当成成功。
- **快速定位**：看 `unity-build/VeilLand3D/VeilLand3D.exe` 的 mtime 是否 > 构建开始时间；完整日志里 grep `error CS` / `Build succeeded`。
- **修复**：重跑 `BuildWindows.Build` **不要加 `| tail`**，保留完整日志确认「构建成功」。
- **预防**：构建后校验 `VeilLand3D.exe` mtime + `grep -i "build succeeded\|error" 完整日志`，确认产物存在再打包上传。

## P6 · PowerShell 读无 BOM 的 .ps1 → 中文文件名/路径乱码

- **症状**：`Compress-Archive` 跑完，`ls download/` 看到输出文件名叫 `甯峰箷涔嬪湴3D_new.zip`（乱码）而非 `帷幕之地3D_new.zip`。
- **根因**：脚本工具写 `.ps1` 默认 UTF-8 **无 BOM**；Windows PowerShell 5.1 读无 BOM 的 `.ps1` 按系统 ANSI 代码页（中文系统=GBK）解码，把脚本里字面量中文路径（`$dst = '...帷幕之地3D_new.zip'`）读成乱码，`Compress-Archive` 就拿乱码当输出文件名。
- **快速定位**：`ls download/` 看文件名是否乱码；`ls -b` 看真实字节（`\345\270\267...` = 正确的 UTF-8 帷…）。注意：**只有脚本里的字面量会乱码**；zip 内部条目名是 .NET 枚举文件系统得到的 Unicode，不会乱（Node 读 central directory 可确认，中文条目带 `[u8]` 标志且解码正确）。
- **修复**：① 让 `Compress-Archive` 输出到 **ASCII 临时名**（如 `3D_new.zip`），再用 bash `mv download/*_new.zip download/帷幕之地3D.zip` 改名（bash 走 UTF-8，不会乱）；② 或给 `.ps1` 加 UTF-8 BOM（`printf '\xEF\xBB\xBF' > x.ps1`）。
- **预防**：**打包脚本里一律「ASCII 临时名 + bash `mv` 中文名」**，别在 `.ps1` 字面量里写中文；或确保 `.ps1` 带 BOM。

## 一图流：上线正确顺序（每次发客户端包照此走）

1. Unity 构建（保留完整日志，确认成功）→ `unity-build/VeilLand3D/` 里有新 `VeilLand3D.exe`。
2. `Compress-Archive` 打成**真 zip** → `head -c 4` 校验是 `PK`。
3. `node _reset-remote.mjs <密码>` 删远端旧包。
4. `node upload-client-zip-resume.mjs <密码>` 续传上传。
5. `curl -s -r 0-15 '<encode后的下载URL>' | xxd` 校验远端也是 `PK`；`curl -I` 确认 200 + Content-Length 与本地一致。
6. 本地 `md5sum` 与远端（可 `curl` 拉回一小段比对或直接相信 size+魔数）一致后，才算上线完成。
